# 20. 状态机、回调与模块化设计

## 学习目标

- 将复杂控制逻辑拆成明确的状态、事件和转移。
- 通过表驱动或函数接口降低大量嵌套 if/else 的复杂度。
- 明确模块边界、错误处理、重入和回调生命周期。

## 1. 状态机示例

~~~c
#include <stdbool.h>

typedef enum {
    DEVICE_IDLE = 0,
    DEVICE_ACTIVE,
    DEVICE_ERROR
} device_state_t;

typedef enum {
    EVENT_START = 0,
    EVENT_UPDATE,
    EVENT_STOP,
    EVENT_FAULT,
    EVENT_RESET
} device_event_t;

typedef struct {
    device_state_t state;
    unsigned int update_count;
} device_t;

static bool device_dispatch(device_t *device, device_event_t event)
{
    if (device == NULL) {
        return false;
    }

    switch (device->state) {
    case DEVICE_IDLE:
        if (event == EVENT_START) {
            device->state = DEVICE_ACTIVE;
            device->update_count = 0U;
            return true;
        }
        return false;

    case DEVICE_ACTIVE:
        switch (event) {
        case EVENT_UPDATE:
            ++device->update_count;
            return true;
        case EVENT_STOP:
            device->state = DEVICE_IDLE;
            return true;
        case EVENT_FAULT:
            device->state = DEVICE_ERROR;
            return true;
        default:
            return false;
        }

    case DEVICE_ERROR:
        if (event == EVENT_RESET) {
            device->state = DEVICE_IDLE;
            return true;
        }
        return false;

    default:
        /* 对损坏或未初始化的状态采取明确策略。 */
        device->state = DEVICE_ERROR;
        return false;
    }
}
~~~

该代码演示转移规则。真实设备还应定义进入/退出动作、超时、事件优先级、故障锁存和诊断记录。update_count 的最大值及溢出策略也应根据用途明确。

## 2. 把模块接口和实现分开

建议一个模块至少明确：

- 公开头文件：类型、函数原型、错误码和调用约束；
- 私有实现：内部状态、辅助函数和硬件细节；
- 所有权：对象由谁创建、初始化和销毁；
- 时序：同步调用还是异步回调，调用上下文是什么；
- 错误路径：失败后状态是否保持，是否允许重试；
- 测试接口：能否在不接入真实硬件时替换依赖。

## 3. 避免常见设计问题

- 不要在一个函数里混合协议解析、硬件访问、业务状态和日志输出。
- 不要在未定义重入行为的情况下从回调中再次触发同一个状态机。
- 不要在异步回调中保存指向短生命周期栈变量的指针。
- 不要忽略非法事件；应明确拒绝、记录或进入安全状态。
- 状态转移应集中管理，避免多个函数分别修改同一个状态字段。
- 复杂状态机可考虑转移表，但表驱动并不自动让设计正确，仍要覆盖非法组合。

## 练习与验收

1. 为一个传感器采集模块定义初始化、采集、故障和恢复状态。
2. 给每个状态列出允许事件、拒绝事件和进入/退出动作。
3. 将硬件读取替换为 mock 函数，验证状态机不依赖真实设备。
4. 为每条合法转移和非法事件编写单元测试。

**验收标准：** 状态转移可追踪；模块接口清晰；非法事件和故障恢复有明确策略；核心逻辑可脱离硬件测试。
