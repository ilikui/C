# 16. 指针进阶与函数指针

## 学习目标

- 区分对象指针、指针数组、数组指针和函数指针。
- 用函数指针实现回调，而不是把不同函数硬编码在一个大分支里。
- 明确回调函数的参数、返回值和生命周期约定。

## 1. 先看声明含义

~~~c
int *p;             /* p 指向 int */
int *items[4];      /* items 是含 4 个 int 指针的数组 */
int (*row)[4];      /* row 指向含 4 个 int 的数组 */
int (*operation)(int, int); /* operation 指向函数 */
~~~

判断复杂声明时，从变量名开始，优先结合括号，再向外阅读。括号会改变结合顺序。

## 2. 用函数指针实现可替换策略

~~~c
#include <stdbool.h>
#include <stddef.h>
#include <stdio.h>

typedef int (*binary_op_t)(int lhs, int rhs);

static int add(int lhs, int rhs)
{
    return lhs + rhs;
}

static int multiply(int lhs, int rhs)
{
    return lhs * rhs;
}

static bool calculate(binary_op_t op, int lhs, int rhs, int *result)
{
    if (op == NULL || result == NULL) {
        return false;
    }

    *result = op(lhs, rhs);
    return true;
}

int main(void)
{
    int result = 0;

    if (calculate(add, 3, 4, &result)) {
        printf("add=%d\n", result);
    }
    if (calculate(multiply, 3, 4, &result)) {
        printf("multiply=%d\n", result);
    }
    return 0;
}
~~~

这个例子展示接口形态；实际工程还需要确认整数溢出是否可能发生。对于有溢出风险的运算，应增加范围检查或使用适当的数据类型。

## 3. 回调接口设计清单

- 函数指针类型要表达真实的参数和返回值类型，不要通过强制类型转换掩盖不匹配。
- 明确回调何时被调用、是否可能重复调用、是否可能在调用者返回后继续使用。
- 若回调携带上下文，优先使用显式的 context 指针，并说明由谁拥有其生命周期。
- 若回调可能重入，检查回调内是否会再次触发同一接口。
- 不要把普通函数指针与对象指针互相转换；标准 C 不保证这类转换可移植。

## 常见错误

1. 把指针数组和数组指针混为一谈。
2. 调用空函数指针或生命周期已经结束的回调上下文。
3. 函数签名不一致，却使用强制转换压制编译器警告。
4. 回调内部修改共享状态，却没有定义重入和并发规则。

## 练习与验收

1. 定义一个比较函数类型，并用回调实现升序和降序比较。
2. 画出指针数组与数组指针的内存关系图。
3. 给回调接口增加 context 参数，并写清楚 context 的所有权。
4. 使用严格警告编译，确保没有函数指针类型不匹配警告。

**验收标准：** 能准确解释每个声明；回调接口不依赖不安全强制转换；空指针和上下文生命周期均有约定。
