# 36. 嵌入式内存分区与启动期初始化

## 学习目标
- 认识 Flash、RAM、栈、堆、.data、.bss 等常见区域。
- 理解 C 对象存储期与链接器/启动代码的关系。
- 使用 map 文件验证内存占用，而不是凭变量声明猜测。

## 典型内存视图
```mermaid
flowchart TD
    A["非易失存储 Flash / ROM"] --> B["程序代码与只读数据"]
    A --> C["初始化数据的装载映像"]
    D["易失存储 RAM"] --> E[".data：有初值的静态存储期对象"]
    D --> F[".bss：零初始化的静态存储期对象"]
    D --> G["栈：调用帧与自动对象"]
    D --> H["堆：动态分配对象（若使用）"]
    C -. "启动时复制" .-> E
    I["启动代码"] --> J["初始化运行环境"]
    J --> E
    J --> F
    J --> K["进入 main"]
```

这是常见实现模型，不是 ISO C 强制规定的物理布局。具体分区、栈方向、是否使用堆以及启动流程都由 MCU、工具链、链接脚本和运行库决定。

## C 语言层面要区分什么
- **静态存储期对象**：生命周期覆盖整个程序执行期；未显式初始化的对象按语言规则零初始化。
- **自动存储期对象**：通常是函数内非 static 局部变量，生命周期受执行块控制。
- **动态分配对象**：由 malloc/calloc/realloc 分配，直到释放或程序终止。
- **只读常量与字符串字面量**：实现可能将其放在只读区域；不要依赖特定地址或可写性。

```c
#include <stdint.h>

static uint32_t boot_count;
static const uint16_t table[3] = { 10U, 20U, 30U };

void process_sample(void)
{
    uint16_t local_sample = 0U;
    (void)local_sample;
}
```

变量的具体段位置需结合编译器、链接器配置和 map 文件判断。文件作用域的 static 影响链接属性，函数内 static 则影响对象存储期。

## 启动期常见任务
1. 设置初始栈指针并执行平台要求的低级初始化。
2. 将初始化数据从装载地址复制到运行地址。
3. 清零未初始化静态存储区。
4. 初始化时钟、内存保护或运行库（依平台而定）。
5. 调用运行库初始化钩子（如工具链需要），最后进入 main。

## 易错点
- 大型局部数组可能耗尽有限栈空间。
- 大型静态缓冲区会占用 RAM，即使没有动态分配。
- const 不保证对象一定在 Flash。
- 修改启动代码可能导致全局变量未初始化或运行库不可用。
- map 文件中的段大小不等于运行时峰值栈/堆占用。

## 练习与验收
建立含全局数组、静态局部变量、普通局部数组和常量表的小程序，查看 map/段信息。验收：能说明每个对象的 C 存储期，并指出具体地址分配依据来自哪份工具链配置。
