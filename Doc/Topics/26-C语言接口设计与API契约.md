# 26. C 语言接口设计与 API 契约

## 学习目标
- 设计调用方容易理解、实现方容易维护的 C API。
- 明确参数、返回值、对象所有权、生命周期和错误语义。
- 使用头文件隐藏实现细节，减少模块之间的耦合。

## API 设计流程
~~~mermaid
flowchart TD
    A["明确调用场景"] --> B["定义输入与输出"]
    B --> C["约定所有权和生命周期"]
    C --> D["定义错误语义"]
    D --> E["编写头文件契约"]
    E --> F["实现与测试"]
~~~

## 1. 让契约写在接口附近
~~~c
#ifndef FILTER_H
#define FILTER_H

#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

typedef struct {
    int32_t value;
    bool valid;
} filter_result_t;

/* 返回 false 表示参数不合法；此函数不分配动态内存。 */
bool filter_init(uint32_t window_size);

/* result 必须指向可写对象；仅在返回 true 时结果有效。 */
bool filter_push(int32_t sample, filter_result_t *result);

#endif
~~~

示例中的状态存储方式需要与实际实现一致；若滤波器实例不应使用全局状态，建议将内部状态放进不透明句柄或调用方提供的实例结构体中。

## 2. API 契约检查表
- **输入：** 是否允许 NULL？长度是否可以为 0？单位和取值范围是什么？
- **输出：** 失败时输出参数是否保持不变？返回值表示成功还是数据本身？
- **所有权：** 谁分配、谁释放？返回的指针由谁管理？
- **生命周期：** 指针在函数返回后是否仍有效？对象何时可以销毁？
- **并发：** 是否允许多个任务同时调用？是否允许在 ISR 中调用？
- **错误：** 调用者应如何区分参数错误、超时和硬件故障？

## 3. 避免模糊的所有权
不要返回指向局部变量的地址，也不要让调用方猜测返回的缓冲区是否需要释放。若 API 返回内部静态缓冲区，应明确它会在何时被覆盖，以及是否线程安全。

## 练习与验收
1. 为字符串解析器设计头文件，定义输入缓冲区、长度和错误返回。
2. 为动态对象明确 create/destroy 配对关系。
3. 写一份 API 使用示例，并标注所有权和生命周期。
4. 检查 API 是否明确说明 ISR 可调用性与并发限制。

**验收标准：** 调用方无需阅读实现即可正确使用接口；所有权、错误和生命周期均有明确约定。
