# 17. 内存布局、对齐与未定义行为

## 学习目标

- 理解对象表示、对齐要求和结构体填充。
- 识别越界访问、未对齐访问、悬空指针和严格别名相关风险。
- 区分标准 C 保证的行为与目标平台特有的行为。

## 1. 结构体可能包含填充

~~~c
#include <stddef.h>
#include <stdio.h>

struct sample {
    char flag;
    int value;
    short code;
};

int main(void)
{
    printf("sizeof(struct sample)=%zu\n", sizeof(struct sample));
    printf("offset(value)=%zu\n", offsetof(struct sample, value));
    return 0;
}
~~~

输出结果由实现决定。成员之间和结构体尾部可能存在填充字节；不要假定不同编译器、ABI 或处理器上的布局完全相同。

## 2. 不要把字节缓冲区随意转换成任意类型指针

从外部数据包、文件或字节数组解析数值时，优先检查长度，再使用显式字节解析；对于对象表示的复制，可使用 memcpy，但仍需考虑字节序、类型表示和协议格式。

~~~c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

static bool read_u16_le(const uint8_t *data, size_t length, uint16_t *out)
{
    if (data == NULL || out == NULL || length < 2U) {
        return false;
    }

    *out = (uint16_t)((uint16_t)data[0] |
                      ((uint16_t)data[1] << 8));
    return true;
}
~~~

这种写法明确规定了小端格式，不依赖 CPU 原生字节序，也避免从任意地址解引用 uint16_t 指针。

## 3. 常见未定义行为来源

- 对数组或对象边界之外的地址进行访问。
- 解引用空指针、悬空指针或不满足对齐要求的指针。
- 读取未初始化的自动变量。
- 对有符号整数执行超出可表示范围的算术运算。
- 修改同一个标量对象时产生未排序的冲突访问。
- 通过不兼容的左值类型访问对象，违反有效类型/严格别名规则。
- 使用已释放内存，或重复释放同一分配对象。

## 练习与验收

1. 打印一个结构体的 sizeof 和各成员 offsetof，比较不同成员顺序的结果。
2. 实现一个带长度参数的 32 位小端解析函数。
3. 逐行审查一段指针代码，标记所有可能的越界和生命周期风险。
4. 说明为什么结构体直接写入文件并不自动成为可移植的序列化格式。

**验收标准：** 能解释布局为何依赖实现；解析外部字节时先验证长度；不会用随意的指针强转代替合法的对象访问。
