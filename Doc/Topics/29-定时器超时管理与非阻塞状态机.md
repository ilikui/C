# 29. 定时器、超时管理与非阻塞状态机

## 学习目标
- 用时间戳管理超时，避免忙等和阻塞延时。
- 将长流程拆成每次快速执行的状态转移。
- 正确处理计时器回绕、超时边界和重试次数。

## 非阻塞流程
~~~mermaid
stateDiagram-v2
    [*] --> IDLE
    IDLE --> WAITING: 启动操作并记录起始 tick
    WAITING --> DONE: 收到完成事件
    WAITING --> TIMEOUT: 超过超时阈值
    WAITING --> WAITING: 尚未完成且未超时
    TIMEOUT --> IDLE: 清理/报告错误
    DONE --> IDLE: 消费结果
~~~

## 1. 用差值判断超时
~~~c
#include <stdbool.h>
#include <stdint.h>

/*
 * 适用于无符号 tick 计数器自然回绕的情况。
 * 约定 duration 小于计数器模数的一半，且 now/start 来自同一 tick 时基。
 */
static bool elapsed_at_least(uint32_t now,
                             uint32_t start,
                             uint32_t duration)
{
    return (uint32_t)(now - start) >= duration;
}
~~~

无符号减法按模数运算，因此可以正确处理常见的自然回绕情形，但仍需约束 duration 和调用间隔。不要用 now >= start + duration 作为通用回绕安全判断，因为加法本身可能回绕。

## 2. 每次调用只推进一步
~~~c
#include <stddef.h>
#include <stdint.h>

typedef enum {
    JOB_IDLE,
    JOB_WAITING,
    JOB_DONE,
    JOB_TIMEOUT
} job_state_t;

typedef struct {
    job_state_t state;
    uint32_t started_at;
    uint32_t timeout_ticks;
} job_t;

void job_start(job_t *job, uint32_t now, uint32_t timeout_ticks)
{
    if (job == NULL) {
        return;
    }

    job->started_at = now;
    job->timeout_ticks = timeout_ticks;
    job->state = JOB_WAITING;
}
~~~

真实实现还应定义空指针时的接口契约、完成事件的来源、状态机的并发调用限制和 timeout_ticks 的合法范围。

## 3. 为什么避免忙等
- 忙等会占用 CPU，并可能阻止低优先级工作得到执行。
- 阻塞延时会降低系统对其他事件的响应能力。
- 非阻塞状态机允许主循环或任务继续处理通信、诊断和其他工作。
- 超时处理应包含资源清理、错误记录和重试上限，而不仅是改变状态变量。

## 练习与验收
1. 实现一个等待传感器转换完成的非阻塞流程。
2. 测试 tick 接近最大值时启动、回绕后超时的情况。
3. 为超时、成功、取消和重试上限分别定义状态转移。
4. 检查状态机每次调用的执行时间是否有上界。

**验收标准：** 无忙等；超时边界明确；tick 回绕假设有说明；所有结束路径都能释放或复位资源。
