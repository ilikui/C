# 21. 位操作、寄存器字段与掩码设计

## 学习目标
- 使用无符号整数和位掩码操作标志位。
- 正确提取、设置和清除寄存器字段。
- 识别移位宽度、整数提升和读改写副作用风险。

## 1. 常见操作
~~~c
#include <stdint.h>

#define FLAG_READY (UINT32_C(1) << 0)
#define FLAG_ERROR (UINT32_C(1) << 1)

static uint32_t set_flag(uint32_t value, uint32_t mask)
{
    return value | mask;
}

static uint32_t clear_flag(uint32_t value, uint32_t mask)
{
    return value & ~mask;
}

static uint32_t toggle_flag(uint32_t value, uint32_t mask)
{
    return value ^ mask;
}

static uint32_t get_field(uint32_t value, uint32_t mask, unsigned int shift)
{
    return (value & mask) >> shift;
}
~~~

调用 get_field 时，mask 必须与 shift 对应，且 shift 必须小于类型位宽。移位量为负数或大于等于提升后左操作数位宽会导致未定义行为。构造掩码时应避免对有符号整数执行不安全移位。

## 2. 字段设置
假设一个 32 位寄存器中 bit[7:4] 是模式字段：

~~~c
#include <stdint.h>

#define MODE_SHIFT 4U
#define MODE_MASK  (UINT32_C(0x0F) << MODE_SHIFT)

static uint32_t replace_mode(uint32_t reg_value, uint32_t mode)
{
    return (reg_value & ~MODE_MASK) |
           ((mode << MODE_SHIFT) & MODE_MASK);
}
~~~

真实调用前应确认 mode 的取值范围。掩码可以避免 mode 中超出字段宽度的位污染其他字段，但不会替代输入合法性检查。

## 3. 硬件寄存器特别注意
普通变量上的 value |= mask 与硬件寄存器上的读改写不是一回事。寄存器可能具有写 1 清零、读清零、只写或保留位语义。必须先查芯片手册；某些寄存器应使用专用 SET/CLEAR 寄存器或平台提供的访问宏。

## 常见错误
- 使用 1 << 31 这类可能触及有符号类型边界的表达式。
- 移位量来自外部输入但没有范围检查。
- 清除位时写成 value | ~mask。
- 假定所有寄存器都可以安全读改写。
- 对掩码的位宽、位置和协议定义没有文档说明。

## 练习与验收
1. 实现检测、设置、清除、翻转单个位的函数。
2. 实现一个字段提取函数，并拒绝非法 shift。
3. 为 4 位字段写出合法值、非法值和边界值测试。
4. 找一个 MCU 寄存器，判断它能否安全使用读改写。

**验收标准：** 位操作使用明确宽度的无符号类型；字段掩码与移位量有依据；硬件寄存器操作遵守芯片手册。
