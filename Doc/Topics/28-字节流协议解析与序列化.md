# 28. 字节流、协议解析与序列化

## 学习目标
- 根据明确的协议布局解析字节流。
- 处理长度、端序、字段范围和不完整报文。
- 避免把任意字节缓冲区直接强转为结构体指针。

## 解析流水线
~~~mermaid

    D -- "否" --> X

    F --> G["输出结构化数据"]
~~~

## 1. 安全读取大端 16 位整数
~~~c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

static bool read_be_u16(const uint8_t *data,
                        size_t length,
                        size_t offset,
                        uint16_t *out)
{
    if (data == NULL || out == NULL) {
        return false;
    }

    /* 用减法检查边界，避免 offset + 2 发生 size_t 溢出。 */
    if (offset > length || length - offset < 2U) {
        return false;
    }

    *out = (uint16_t)(((uint16_t)data[offset] << 8) |
                      (uint16_t)data[offset + 1U]);
    return true;
}
~~~

## 2. 解析器必须区分的情况
- **不完整：** 当前缓冲区可能只是分片，需要等待更多字节。
- **格式错误：** 标识、版本、长度或字段编码不符合协议。
- **业务非法：** 语法合法，但数值超出业务允许范围。
- **资源不足：** 目标缓冲区容量不足，不能写越界。

实际协议应定义这些情况是否使用不同错误码。解析器不要假设一次接收就恰好得到一整帧。

## 3. 序列化同样要检查容量
~~~c
static bool write_be_u16(uint8_t *out, size_t capacity,
                         size_t offset, uint16_t value)
{
    if (out == NULL || offset > capacity || capacity - offset < 2U) {
        return false;
    }

    out[offset] = (uint8_t)(value >> 8);
    out[offset + 1U] = (uint8_t)(value & UINT16_C(0x00FF));
    return true;
}
~~~

不要使用 memcpy(out, &struct, sizeof struct) 作为通用协议序列化方案：结构体可能含填充字节，成员布局和端序也可能随实现变化。

## 练习与验收
1. 设计一个含 magic、version、length 和 payload 的小协议。
2. 测试空缓冲区、截断头部、长度过大、非法版本和完整报文。
3. 分别实现大端和小端字段读取。
4. 对每次偏移和长度计算做边界检查，特别关注整数溢出。

**验收标准：** 不越界读取；不依赖本机结构体布局；能够区分不完整输入、格式错误和业务非法。
