## GCC 文档说明

这几个参数是 GNU Make（以及 GCC 编译器）中约定俗成的“隐式标准变量”。
在编写 Makefile 时，推荐使用这些标准变量，因为它们对应了 C 语言程序从预处理、编译到链接的完整生命周期。直接看它们的具体分工：

### 核心参数详解

| 变量名   | 全称与作用                                                                                  | 典型应用场景与示例                                                                                              |
| -------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| CC       | C Compiler 指定使用的 C 语言编译器。                                                        | CC = gcc.exe （也可以是 arm-none-eabi-gcc 等交叉编译器）                                                        |
| CFLAGS   | C Flags 传给编译阶段的选项。控制警告级别、调试信息和代码优化。                              | -Wall -Wextra（开启几乎所有警告） -g（生成调试信息，方便 GDB 调试） -O2（代码优化） -std=c99（指定 C 语言标准） |
| CPPFLAGS | C Preprocessor Flags 传给预处理器的选项。主要用于指定头文件路径和定义全局宏。               | -I./inc（指定头文件搜寻路径） -DDEBUG（在代码中全局定义 #define DEBUG 宏开关）                                  |
| LDFLAGS  | Linker Flags 传给链接器的外部选项。主要是告诉链接器去哪里找库文件，或者传递特殊的链接指令。 | -L./libs（告诉链接器第三方库文件的存放路径） -Wl,-Map=output.map（让链接器生成内存映射文件）                    |
| LDLIBS   | Linker Libraries 指定需要链接的具体库名称。                                                 | -lm（链接数学库 math） -lpthread（链接多线程库） -lws2_32（Windows 下链接网络套接字库）                         |

---

### 🛠️ 它们在 GCC 编译命令中是如何组合的？

标准的 Makefile 隐式规则中，一个标准的 C 文件从源码到生成可执行文件的过程，这些变量会像接力赛一样按顺序拼接：

### 1. 编译阶段（.c 变 .o）

预处理和编译合在一起时，CPPFLAGS 和 CFLAGS 会被塞给编译器：

```patch
$(CC) $(CFLAGS) $(CPPFLAGS) -c main.c -o main.o# 实际展开形如：# gcc.exe -Wall -Wextra -g -I./inc -c main.c -o main.o

```

### 2. 链接阶段（.o 变 .exe）

多个目标文件生成最终程序时，LDFLAGS 和 LDLIBS 会出场。注意：库文件名 LDLIBS 必须放在最后面，否则 GCC 可能会因为找不到符号而报错。

$(CC) $(LDFLAGS) main.o -o main.exe $(LDLIBS)# 实际展开形如：# gcc.exe -L./libs main.o -o main.exe -lm

---

### 💡 语法小贴士：?= 代表什么？

在你的这几行代码中，除了 CC = gcc.exe 使用了强行赋值之外，其余四个都使用了 ?=（条件赋值）。

- 它的意思是：如果这个变量在系统环境变量里、或者在执行命令时已经被定义了，就用定义好的值；如果没有被定义，才使用后面给出的默认值。
- 这为你提供了极大的灵活性。例如，在你的 Makefile 中写了 CFLAGS ?= -Wall -Wextra -g，如果你某天想临时做代码性能优化，不需要修改 Makefile，直接在命令行输入即可覆盖它：

mingw32-make CFLAGS="-O3"

既然你提到了这些参数，你是否打算把头文件路径（-I）或特定的宏定义（-D）集成到你刚才的跨目录学习 Makefile 中？如果是的话，我们可以把它们优雅地规范化进去。
